## 摘要

AI 编程助手插件市场正处于**爆发期**，Claude Code 作为新兴平台具有巨大机会。project-doc 的差异化定位在于**文档自动化治理**——一个被 superpowers 等头部插件忽略的痛点。建议优先面向中国开发者市场，以免费策略快速获取用户基础。

### 2.2 功能对比矩阵

| 功能维度 | superpowers | cursor-rules | project-doc | 差距分析 |

**核心发现**: 文档治理是市场空白点。

### 2.3 superpowers 深度分析（标杆）

**基本信息**：
- 作者：Jesse Vincent (obra)
- 版本：5.0.7
- 定位：Core skills Library for Claude Code
- 多平台支持：Claude、Cursor、OpenCode、Gemini CLI

**用户评价洞察**：
- 高频好评："workflow"、"TDD"、"collaboration"
- 痛点："缺少项目管理视角"
- 建议："希望有文档相关技能"

**可借鉴点**：
1. 多平台适配策略（Phase 3 参考）
2. 完整工程化外壳（tests、CI/CD、scripts）
3. 清晰的 README 和 CHANGELOG
4. 版本管理自动化

**需避开点**：
- 功能过于广泛，定位模糊
- 缺少垂直场景深度

**差异化机会**：
- superpowers 专注"怎么写代码"
- project-doc 专注"怎么管理代码产物"
- **互补而非竞争**

### 2.4 间接竞品

| 类型 | 代表 | 对 project-doc 影响 |
|------|------|---------------------|
| 项目管理工具 | Jira、Notion | 低（开发者不愿用） |
| 文档工具 | Confluence、Wiki | 中（与 AI 流程割裂） |
| Git 工具 | GitLab、GitHub | 低（无文档治理） |

**结论**: 间接竞品存在但无法替代 AI 深度集成的价值。

## 三、project-doc 差异化定位

### 3.1 定位声明

```
project-doc 是专为 Claude Code 打造的项目治理专家，
解决开发者"文档追着代码跑"的核心痛点。

区别于通用项目管理工具，project-doc 深度集成 AI 编程流程，
让文档自动化成为开发习惯的一部分。

核心价值：让文档追着代码跑，而非反之。
```

### 3.2 SWOT 分析

| 优势 (S) | 劣势 (W) |
|----------|----------|
| ✅ 深度 Claude Code 集成 | ❌ 新产品，无用户基础 |
| ✅ 文档自动化（市场空白） | ❌ 功能较单一 |
| ✅ 多语言模板（中文优先） | ❌ 缺少可视化界面 |
| ✅ 自动触发机制 | ❌ 缺少团队协作功能 |

| 机会 (O) | 威胁 (T) |
|----------|----------|
| ✅ AI 编程工具爆发期 | ❌ superpowers 等竞品扩展功能 |
| ✅ 中国开发者市场空白 | ❌ 用户习惯手动管理文档 |
| ✅ Claude Code 生态早期 | ❌ 平台政策不确定性 |
| ✅ 互补定位而非竞争 | ❌ 开发者教育成本 |
